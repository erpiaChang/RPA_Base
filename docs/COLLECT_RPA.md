# 수집 RPA — 확정사항과 Phase A 조사

이 문서가 수집 RPA 의 **확정본**이다. 메일 사이트 화면 셀렉터는 git 밖 `docs/local/<사이트>.md` 에 있다.

## ★ 왜 브라우저를 쓰나 — IMAP / 메일 API 를 **일부러** 쓰지 않는다

메일을 읽는 가장 쉬운 길은 IMAP 이나 메일 API 다. 그것을 **의도적으로 피했다**
(사용자 확정 2026-09-08).

이 기능을 나중에 **사이트 직접 수집**에도 쓸 것이기 때문이다. 사이트에는 API 가
없으니 결국 브라우저를 몰아야 하고, 그 역량을 만드는 것이 목적이다. 그래서
연동이 쉬운 메일(Gmail 등)로 갈아타는 것도 답이 아니다.

**"IMAP 으로 바꾸면 간단해진다" 는 제안은 이미 검토하고 버린 선택지다.**
2차 인증을 매번 통과하는 것, 기기 신뢰 등록을 쓰지 않는 것도 같은 이유다 —
인증을 뚫는 과정 자체가 사이트 직접 수집의 예행연습이다.

## 1. 사용자 확정 (2026-09-08)

| 항목 | 확정값 |
| --- | --- |
| 대상 휴대폰 | **Android 우선.** iPhone 은 추후 확장 여지로 남긴다 |
| 기기 신뢰 등록 | **쓰지 않는다.** 인증을 매번 통과하는 것 자체가 목표다 — 나중에 할 **사이트 직접 수집의 예행연습** |
| 차수 | **날짜별로 001 부터 재시작** |
| 메일 선별 | 발신자 주소 **완전일치** AND 제목의 **`[사이트명]` 완전일치** AND **읽지 않은 메일** |
| 날짜 조건 | 설정 `mail_days_back`. `0`=오늘만, `1`=어제까지, **`-1`=날짜조건 없음** |
| 인증번호 자동 추출 실패 | **그냥 실패로 중단.** 사람이 입력하는 반자동 구간은 두지 않는다 |
| 설정값 | 사용자가 `config/settings.local.json` 에 직접 채운다. 코드에 쓰지 않는다 |

### 만든 설정 키

정의는 `config/fields_collect.py` 의 `DEFAULTS` (설명서는 `docs/SETTINGS.md` 3~5절).

| 키 | 뜻 |
| --- | --- |
| `mail_url` | 메일 사이트 로그인 페이지 URL |
| `mail_user_id` / `mail_password` | 계정 (비밀번호는 `dpapi:` 로 감싸 저장, 09-17) |
| `mail_senders` | 발신자 주소 완전일치 목록. 비면 발신자 조건 없음 |
| `mail_sites` | 제목 대괄호 안 사이트명 완전일치 목록 |
| `mail_unread_only` | 읽지 않은 메일만 대상 (`false` 면 읽은 메일도) |

| `sms_source` | 인증번호 경로 `phonelink`(USB 없이) / `adb` / `auto` |
| `adb_path` | adb 실행 파일 경로. 비우면 PATH 에서 찾는다 |

타임아웃도 추가: `page_load` 30s / `sms_code` 120s / `download` 60s.

## 3. 인증번호(SMS) 획득 경로 — 후보 비교

요구: **폰이 PC 옆에 없어도** 자동으로 인증번호를 읽어야 한다 (사용자 요청).
이 요구가 후보를 크게 갈랐다.

| 방법 | 원격(폰이 멀리) | 권한/설치 | 읽는 방식 | 판정 |
| --- | --- | --- | --- | --- |
| **문자 전달 앱 + 웹훅** (SMS Forwarder / SMS Gateway / MacroDroid·Tasker) | **가능** — 폰에 데이터만 있으면 된다 | 폰에 앱 1개 + SMS 권한 | PC 로컬 수신함(HTTP·파일) | **1순위 후보** |
| **Google 메시지 웹** (`messages.google.com/web`) | **가능** — 폰이 인터넷에 있으면 된다 | 기본 문자앱이 Google 메시지여야 한다 | **Playwright** (이미 쓰는 스택 그대로) | 2순위 |
| **휴대폰 연결(Phone Link)** | **불확실** | MS 계정 + 폰 연결 | pywinauto UIA (이 프로젝트 강점) | 3순위 |
| **adb (USB)** | 불가 — USB 를 꽂아야 한다 | USB 디버깅 허용 | `content query content://sms` | **실측 결과 읽힌다.** 폰이 옆에 있을 때의 기본 경로 |
| OCR / 화면 미러링 | — | — | — | **쓰지 않는다** (틀리면 계정 잠김) |

### 근거와, 아직 확인하지 못한 것

- **Phone Link 원격 동작이 불확실하다.** MS 공식 문서는 "PC 와 Android 가 켜져 있고
  인터넷에 연결돼 있어야 한다"고만 쓰지만, 다른 문서·사용자 보고는 Android 쪽은
  **블루투스와 Wi-Fi 가 모두 켜져 있어야 한다**고 말한다. 즉 폰이 멀리 있을 때
  문자가 계속 들어오는지 **실측 전에는 단정할 수 없다.** 폰 연결 후 실제로 확인해야 한다.
- **Google 메시지 웹은 QR 페어링이 없어지는 중이다** (2026년, 미국부터).
  같은 Google 계정 로그인 + 이모지 확인 방식으로 바뀌고 있다. 폰은 인터넷에 있어야 한다.
  국내 Android 는 기본 문자앱이 삼성 메시지인 경우가 많아 **기본앱 변경이 전제**다.
- **adb 는 읽히지만 원격 요구를 못 채운다.** Android 9 이상은 막히는 경우가 많다고 알려져
  있으나 **이 기기에서는 읽혔다**(아래 실측). 다만 USB 를 꽂아야 하므로
  "폰이 멀리 있어도"라는 요구와는 맞지 않는다.
- 문자 전달 앱은 **폰이 어디 있든 상관없다**는 점에서 요구와 정확히 맞는다.
  다만 앱 선택·설치·권한은 사용자 결정이 필요하고, 인증번호가 외부 서버를 거치지 않도록
  **PC 로 직접 보내는(로컬 HTTP 수신) 구성**을 골라야 한다.

### 실측 결과 — adb 로 문자를 읽을 수 있다 (2026-09-08)

**예상과 달리 막히지 않았다.** 갤럭시 SM-A000N(One UI)에서 권한 거부 없이 읽혔다.

```
기기: SERIAL00001  device  product:devcode  model:SM_A000N
adb shell content query --uri content://sms/inbox --projection address:date:body --sort "date DESC"
Row: 0 address=0800000000, date=<epoch ms>, body=...
```

| 확인 | 결과 |
| --- | --- |
| USB 디버깅 허용 | 필요하다. 파일 전송(MTP)만으로는 `adb devices` 에 안 잡힌다 |
| `READ_SMS` 권한 | **문제되지 않았다.** `Permission Denial` 없음 |
| 정렬 | `--sort` 값을 **따옴표로 감싸야 한다.** 안 감싸면 adb 가 폰 셸에 이어붙이면서 `date DESC` 가 쪼개져 `Unsupported argument: DESC` 로 실패한다 |
| `LIMIT` | `--sort` 가 받지 않는다. 건수는 받은 뒤에 자른다 |
| 성공 판정 | `content query` 는 **실패해도 종료코드 0 에 사용법을 출력한다.** `Row:` 로 시작하는 줄이 있는지로만 판정한다 |
| 날짜 | `date` 는 epoch **밀리초** |

**남은 제약**: adb 는 USB 연결이 전제라 "폰이 멀리 있어도"라는 요구는 못 채운다.
가까이 있을 때의 기본 경로로는 쓸 수 있다. 원격이 필요하면 문자 전달 앱 경로를 추가한다.

**권한 범위에 대한 주의**: USB 디버깅 허용은 "문자만"이 아니라 그 PC 에 adb 전권을 준다.
Android 에 "문자만 허용"은 없다. 그래서 제한은 **PC 쪽 코드**에 뒀다 —
`collect/sms.py` 는 `adb devices` 와 `content://sms/inbox` 조회만 실행하고,
`pull` / `push` / `install` / `input` / `screencap` 등은 실행 직전에 막는다
(조사용 `tools/probe_sms.py` 는 09-18 에 지웠다).
본문은 파일로 저장하지 않는다. 되돌리려면 폰에서 **USB 디버깅 승인 취소**.

### 남은 확인 (Phase B 에서)

- 메일을 **열지 않고** 목록에서 첨부만 받을 수 있는가. 열면 읽음 처리되어
  "미읽음만" 조건과 충돌한다. 목록의 첨부 링크는 메일 키만 갖고 있다 (셀렉터는 git 밖 `docs/local/<사이트>.md`)
- 목록의 수신일시가 `오늘 13:13` 처럼 상대 표기로 나온다. `mail_days_back` 판정에
  그대로 쓸 수 없다. 상세검색의 기간 조건으로 서버에서 거르는 쪽이 안전하다

### 다음 실측

폰이 옆에 있는 구성은 **adb 로 확정 가능하다**(`sms_source="adb"`). 원격까지 필요하면:

1. 문자 전달 앱 후보 1개를 정해 PC 로컬 수신 → 도착 확인
2. Phone Link 연결 후 **폰을 블루투스 범위 밖으로 두고** 문자가 계속 오는지 확인

`sms_source` 확정은 사용자 결정 사항이다. 그 전까지 인증 코드를 쓰지 않는다.

## 3-2. USB 없이 문자 읽기 (2026-09-08 조사)

USB 케이블을 쓰지 않는 경로를 조사했다.

| 방법 | 판정 | 근거 |
| --- | --- | --- |
| **adb 무선 디버깅** | 대안 | Android 11+ 기본 기능. **읽는 코드가 USB 때와 완전히 같다.** 케이블만 빠진다. 같은 네트워크 필요 |
| 블루투스 MAP | **불가에 가깝다** | Windows 에 쓸 수 있는 API·라이브러리가 없다. OBEX 위의 MAP 클라이언트를 직접 구현해야 한다 |
| 휴대폰 연결(Phone Link) | 보류 | 문자를 PC 앱에서 UIA 로 읽는 방식. 원격 동작이 불확실하고 앱 UI 변경에 묶인다 |
| 문자 전달 앱 + 로컬 웹훅 | 원격까지 필요할 때 | 폰이 다른 네트워크에 있어도 된다. 앱 설치·권한이 필요하다 |

### adb 무선 디버깅

폰: 설정 → 개발자 옵션 → **무선 디버깅** 켜기.
[기기 페어링] 의 `IP:페어링포트` + 6자리 코드로 한 번 페어링하고,
무선 디버깅 화면 상단의 `IP:연결포트` 로 연결한다. **두 포트는 다르다.**

```
.venv\Scripts\python.exe -m tools.test_adb_wireless --pair 192.0.2.50:37199 --code 123456
.venv\Scripts\python.exe -m tools.test_adb_wireless --connect 192.0.2.50:41253
```

연결에 성공하면 `adb_wireless_address` 에 저장되고, 이후 수집 실행은
`check_device()` 가 자동으로 무선 연결을 먼저 시도한다.

| 제약 | 내용 |
| --- | --- |
| 네트워크 | PC 와 폰이 **같은 네트워크**여야 한다. 폰이 밖에 있으면 안 된다 |
| 포트 변경 | 폰 재부팅 / Wi-Fi 변경 시 **연결 포트가 바뀐다.** 페어링은 유지된다 |
| 허용 명령 | 화이트리스트에 `pair` / `connect` / `disconnect` 만 추가했다. 데이터 접근 명령은 여전히 문자 조회뿐이다 |

## 3-3. 인증 문자 읽기 — 초기 세팅 (2026-09-08 확정)

사용자 환경마다 다르다. **설정 세 개의 조합**으로 정해지고, 잘못된 조합은
실행 전에 막는다. 판정은 `collect/auth_code.py` 한 곳에서만 한다.

| 설정 | 값 | 뜻 |
| --- | --- | --- |
| `phone_os` | `android` / `ios` | 인증 문자를 받는 휴대폰 |
| `sms_source` | `phonelink` / `adb` / `auto` | 읽는 방법 |
| `adb_connection` | `usb` / `wireless` | adb 를 쓸 때의 연결 방식 |

### 경로별 전제

| 경로 | 케이블 | 네트워크 | 그 밖에 필요한 것 |
| --- | --- | --- | --- |
| `phonelink` | 불필요 | **폰이 인터넷에 있으면 된다** | PC 의 [휴대폰 연결] 앱이 `연결됨`. 폰에서 [모바일 데이터를 통한 동기화] 허용 |
| `adb` + `usb` | **필요** | 불필요 | [개발자 옵션 → USB 디버깅] + 폰의 허용 창 승인 |
| `adb` + `wireless` | 불필요 | **PC 와 폰이 같은 네트워크** | 한 번 페어링 후 `adb_wireless_address` |

`auto` 는 **phonelink 를 먼저** 보고, 준비가 안 됐으면 adb 로 넘어간다.
둘 다 준비되지 않았으면 무엇을 해야 하는지 적어서 중단한다.

### 기본값 없음

기본값은 없다 — 위 표의 선택지만 있고, 필요한 값이 비면 실행 창 [실행] 이 '입력 필요' 로 잠긴다.
그 밖에 `sms_senders`(발신번호 **목록**, 완전일치, 비우면 조건 없음), `sms_keyword`(인증 문자를 고르는 말).

### iPhone

`phone_os="ios"` 는 **명시적으로 중단**시킨다. adb 는 Android 전용이라 애초에 불가능하고,
[휴대폰 연결] 로 iPhone 문자를 읽는 경로는 **실측한 적이 없다.**
추측으로 동작하는 척하지 않는다.

> 확장 지점: iPhone 을 연결해 `tools/probe_phone_window.py --dump` 로 대화 목록·대화창 구조를
> 조사한 뒤, `auth_code._check_combination()` 의 iOS 차단을 푼다.
> iPhone 은 블루투스 연결 중에만 문자가 보이는 것으로 알려져 있어(미검증),
> 조사 항목에 **폰을 멀리 뒀을 때 문자가 계속 들어오는지**를 반드시 넣는다.

### 사전 점검

```
.venv\Scripts\python.exe -m tools.test_collect --check      설정 조합 + 준비 상태 (로그인 안 함)
.venv\Scripts\python.exe -m tools.test_collect --sms-only   설정된 경로로 문자가 읽히는지
```

`--check` 는 실제 사용 경로까지 정해서 보여준다.

```
휴대폰: android
설정된 경로: phonelink
실제 사용 경로: phonelink
휴대폰 연결 앱: 휴대폰과 연결 — 준비됨
```

### [휴대폰 연결] 앱은 **자동으로 띄운다** (2026-09-15)

앱 창이 없으면 RPA 가 직접 띄운다. 예전에는 그 자리에서 멈췄다.

    10:14:34 [ERROR] [휴대폰 연결] 앱 창을 찾지 못했다. 앱을 실행하고 ...

**프로세스는 살아 있는데 창이 트레이로 내려가 있으면** 이렇게 끝났다.
더 나쁜 것은, 재연결·새로고침 코드가 이 지점 **뒤에** 있어서 닿지도 못한 것이다.

#### ★ 설치 경로를 쓰지 않는다 — PC 마다 다르다

[휴대폰 연결] 은 스토어(UWP) 앱이라 설치 위치가 **PC 마다 다르고 업데이트할
때마다 바뀐다.**

    C:\Program Files\WindowsApps\Microsoft.YourPhone_<버전>_x64__8wekyb3d8bbwe\

그래서 경로 대신 **Windows 가 런타임에 풀어 주는 식별자**만 쓴다. 위에서부터 시도한다.

| 순서 | 방법 | 비고 |
| --- | --- | --- |
| 1 | 프로토콜 `ms-phone:` | 앱이 스스로 등록한다. **실측에서 이걸로 붙었다** |
| 2 | `Get-StartApps` 로 AppID 를 찾아 `shell:AppsFolder` | 프로토콜 등록이 깨진 PC 용 |
| 3 | `Get-AppxPackage` 의 PackageFamilyName + `!App` | 2번이 비었을 때 |

2·3번은 **찾아서** 쓴다. 코드에 박아 두지 않는다. 이 PC 의 실측 결과는
`Microsoft.YourPhone_8wekyb3d8bbwe!App` 이었다.

#### 실측 (2026-09-15)

    10:18:59 [WARNING] [휴대폰 연결] 창이 없다. 앱을 띄워 본다.
    10:19:00 [INFO   ] 앱을 띄웠다 (프로토콜 ms-phone:). 창을 기다린다.
    10:19:07 [INFO   ] 휴대폰 연결 앱 준비됨: '휴대폰과 연결' (대화 13건)

**8초.** 실행 → 창 등장 → 연결 확인 → 대화 목록까지.

#### 한계

- **앱을 띄워도 연결까지 되는 것은 아니다.** 폰에서 [Windows와 연결] 을 꺼
  두었으면 창만 뜨고 오프라인이다. 그 뒤는 `reconnect()` 가 맡는다
- **한 실행에서 한 번만** 띄운다 (`_LAUNCH_STATE`). [다시 시도] 와 같은 이유다.
  `reset_retry_state()` 가 실행을 시작할 때 되돌린다
- 띄우지 못해도 거기서 막지 않는다. 뒤이어 `_window()` 가 사람이 읽을
  안내와 함께 예외를 올린다
