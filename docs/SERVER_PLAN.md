# 서버 연동 · 웹 대시보드 — 지금 구조

`docs/BILLING.md` 의 3·4단계(서버 연동·대시보드)를 **만들고 붙인 뒤의 사실**이다. 서버는 Supabase 무료 범위.
표·함수·정책의 원본은 `server/schema.sql`, 적용 순서는 `server/README.md`, 웹은 `web/`.
만들기 전 기획(A 결정용 / B 부록 / C 검토)은 지금 구조가 아니라서 10-06 에 지웠다. 절 이름 D 는 옛 참조를 살리려고 그대로 둔다.
로컬 LLM 처럼 새 조각을 붙일 때 경계를 여기서 확인한다.

# D. 지금 도는 구조 — RPA 와 서버의 역할

## D-1. 한 줄

**RPA 는 일을 하고, 서버는 그 일을 기록·판정·허가한다.** 서버가 죽어도 RPA 는 돌지만
(창이 뜬 뒤 서버 확인을 한 번도 통과하지 못했거나 거부됐으면 [실행] 이 잠긴다), RPA 없이 서버는 아무것도 만들어내지 않는다.

## D-2. RPA (사용자 PC 의 `RPA_1.exe`)

| 역할 | 내용 | 어디 |
| --- | --- | --- |
| 업무 수행 | ERPia 창 조작, 메일 수집, 엑셀 업로드 — 실제 일은 전부 여기서만 | `automation/`, `collect/` |
| 판단 | 어느 기능을 돌릴지, 예약 시각인지, 화면이 잠겼는지, 실패를 어떤 말로 옮길지 | `orchestrator/modules.py`, `utils/schedule.py`, `friendly.py` |
| 보고 | 7종 이벤트를 큐에 넣고 **별도 스레드**가 보낸다. 업무 흐름은 전송을 기다리지 않는다 | `telemetry.py` `Reporter` |
| 서버 확인·PC 바인딩 | 창이 뜰 때 `ingest` 를 **빈 이벤트**로 한 번 부른다 → 처음이면 이 PC 에 묶이고, 다른 PC 에 묶인 빌드면 거부돼 [실행]이 잠긴다 | `telemetry.verify` |
| 끊김 자수 | `logs/run_inflight.json` 을 남겨 두고, 다음 실행이 뜰 때 지난 실행을 `lost` 로 보고 | `telemetry._recover_inflight` |
| 못 보낸 것 보관 | `logs/outbox.jsonl`, 5분마다 재전송, 24시간 지나면 버림 | `telemetry._resend_outbox` |

이벤트 7종: `run_start`(트리거·기능·단계계획) / `step`(상태·건수·경과) / `log`(사용자에게
보이는 글 한 줄) / `attend`(확인할 것) / `heartbeat`(30초, 잠김·일시정지) / `run_end`(결과·요약) /
`idle`(15분, 다음 예약 시각). 묶음은 **2초 또는 20개**, 요청 타임아웃 5초.

내부 값(경로, `auto_id`, 예외 원문, 비밀번호)은 **싣지 않는다.** 문자열은 300자에서 자른다.

## D-4. 대시보드

위쪽 탭 넷 — **요약 · 사용량 · PC · 실행 기록** (주소 `#/...`), PC 한 대 화면에 켜짐·제어·설정·명령 기록, 어디서나
여는 [사용법 질문] 옆 패널. PC 가 실행 중이면 설정 칸·[저장] 이 잠긴다(서버도 423). 실시간 구독이 아니라 폴링.
로그인은 이메일+비밀번호, 가입 화면 없음, 세션은 `sessionStorage`. 쓰기는 RPC 셋(`send_command`·`set_device_settings`·`ask_question`)뿐이다.

**할 수 없는 것**: 기기 폐기, 사용자 추가, 비밀번호·PC 경로 바꾸기. 앞 둘은 SQL Editor 몫이다.

## D-5. 경계선 — 누가 무엇을 못 하나

| | RPA | 서버 |
| --- | --- | --- |
| ERPia 화면 조작 | **한다** | 못 한다 (영원히) |
| 실행을 시작/중지 | 한다 (사람·예약·**가져간 원격 명령**) | **명령을 남긴다** — 실행 여부는 RPA 가 판정한다 (잠김·실행 중·확인 전이면 거절, D-7) |
| 설정 | 받아서 저장·적용 (실행 중이면 끝난 뒤) | **보관·검사한다** — 허용 키만, 비밀번호 없음 |
| 무엇이 실패인지 판단 | **한다** (`friendly.py`) | 받은 상태값을 그대로 믿는다 |
| 끊김 판정 | 다음 실행 때 자수 | **한다** (10분 무응답) |
| 여러 PC·업체를 한눈에 | 못 한다 | **한다** |
| 데이터 보존·삭제 | 로그는 로컬에만 | **한다** (180일) |
| 과금 근거 | 단계 상태(`done`·`skipped`·실패)를 보낸다 | **센다** (`refresh_usage` 가 `run_steps` 에서, D-9) |

## D-7. 원격 설정·명령·자동 켜기 (09-28, 사용자 요청)

**서버는 여전히 PC 를 부르지 않는다.** RPA 가 30초마다 `poll` 을 부르고 응답으로 설정·명령을 가져간다.

| 결정 (사용자 확정 09-28) | |
| --- | --- |
| 웹에서 바꾸는 설정 | 비밀번호를 뺀 전부. PC 마다 다른 경로(ERPia 위치·엑셀 폴더)도 뺀다 — `REMOTE_KEYS` = `private.clean_settings` |
| 제어할 수 있는 사람 | admin + 그 업체의 owner (`private.can_control`). viewer 는 보기만 |
| 일시정지 | **예약만** 멈춘다 (창 [예약] 탭의 [일시정지] 와 같다). 도는 실행은 [RPA 종료] 로 |
| 실행 중 설정 | **바꿀 수 없다** (09-29) — 웹 칸이 잠기고 `set_device_settings` 가 423 |
| 꺼져 있을 때 | 로그온 때 켜고, 5분마다 "안 떠 있으면 켜기" (`utils/autostart.py`). 처음 켤 때 동의를 받는다 |

| 표·함수 | |
| --- | --- |
| `device_settings` | PC 하나에 한 행. `settings` jsonb + `version`(바뀔 때마다 +1) + `locked_modules`(기능 고정 빌드) + 누가·언제 |
| `commands` | `start`·`stop`·`pause`·`resume` + 기능 + 보낸 사람. **10분 만료**, `taken_at` 으로 한 번만 간다, 30일 보관 |
| `private.bind_device` | 빌드 ID + PC 바인딩 판정. `ingest` 에서 떼어 `poll` 과 같이 쓴다 (보안 판정을 두 벌로 두지 않는다) |
| `poll` | PC 가 부른다. 명령 결과를 받고, PC 에서 고친 설정은 **PC 가 서버 최신판을 받았을 때만** 받는다(웹 쪽이 이긴다), 새 판이면 설정을, 남은 명령을 돌려준다. `last_seen_at` 을 새로 해 웹의 "켜져 있음" 이 된다 |
| `set_device_settings` | 웹. `base_version` 이 다르면 409 — 그 사이 바뀌었다 |
| `send_command` | 웹. 못 가져간 명령이 5개면 429 |

반응 시간: 프로그램이 켜져 있으면 30초 안, 꺼져 있으면 자동 켜기(최대 5분) + 30초. **PC 전원이 꺼졌거나 로그온 전이면
켤 수 없다** — UI 자동화에 바탕화면이 필요하다. 원격 [실행] 도 예약 회차처럼 잠긴 화면이면 거절한다.

| 자리 | 지금 | LLM 이 할 수 있는 것 |
| --- | --- | --- |
| 실패 해석 | `friendly.py` 의 **고정 규칙표** | 규칙에 없는 예외를 사람 말로. 화면 조작 결정에는 쓰지 않는다 |
| 화면 조사 | `docs/CONTROLS.md` 에 사람이 적은 식별값 | 새 화면의 Control 트리를 읽고 후보 제안 (**확정은 사람**) |

## D-8. 사용법 질문 — 로컬 LLM (09-28, 사용자 확정)

실제 RPA 를 쓰는 업체 사용자가 웹 대시보드에서 사용법을 물으면 **LLM 전용 PC**(지금은 개발 PC)가 답한다.
모델은 LM Studio 의 `qwen/qwen3-8b` Q4_K_M (Apache 2.0). 연결 방향은 RPA 와 같다 — **LLM PC → 서버로만.** LM Studio 는 이 PC 밖으로 열지 않는다.

```
웹 ─ ask_question ─▶ questions 표 ◀─ llm_take(2초 대기)·llm_write(흘려 쓰기) ─ llm/worker.py ─ 127.0.0.1:1234 LM Studio
 ▲                                                                                   │
 └──────────── 자기 질문 행을 300ms 마다 다시 읽는다 ◀─────────────────────────────────┘
```

| 무엇 | 어떻게 |
| --- | --- |
| 빠르게 | 워커가 서버에서 2초씩 기다리며 0.2초마다 본다(가져가기 0.02~0.05초 실측) · 모델은 켜 둔 채(GPU 전부, TTL 없음) · 시스템 프롬프트(규칙 + 설명서)가 늘 같은 글이라 LM Studio 가 앞부분을 다시 계산하지 않는다 · Qwen3 생각 단계 끔(`/no_think`) · 서버 쓰기는 따로 도는 스레드 |
| 실측 (09-28) | 첫 글자 0.15~0.6초, 초당 약 35토큰, 답 전체 1.4~4.3초 (질문 → 서버에 완성된 답). 설명서 + 규칙 약 5850 토큰 / 문맥 8192 |
| 답의 근거 | `llm/guide.md` 하나. 화면 이름 기준, 내부 값 금지(`probe_llm` 이 본다). 도구·서버 조회는 주지 않는다 |
| 권한 | 질문은 회원 누구나(viewer 포함). 자기 질문만 읽고 admin 은 전부 본다. 워커는 키(sha256 해시만 서버에)로만 `llm_take`·`llm_write` |
| 한도 | 한 사람에 한 번에 하나(409) · 24시간 50개(429) · 답하는 PC 가 15초 넘게 조용하면 받지 않는다(503) · 질문 500자 · 답 4000자 |
| 보관 | **30일 + 사람당 최근 20개** (사용자 확정 09-28, `purge_old` 매일 03:30) — 크기가 '사용자 수 × 20건'(한 건 약 0.4~1KB)으로 묶인다. 1,000명이어도 약 20MB (무료 플랜 DB 한도 500MB). 답을 흘려 쓸 때 생기는 옛 판은 Postgres 가 치워 쌓이지 않는다 |
| 닫기 | 1분 안에 아무도 안 가져가면 `expired`, 답이 2분 멈추면 `failed` — 워커가 꺼져 있어도 cron 이 닫는다 |
| 이어 묻기 | 같은 사람의 10분 안 앞 질문·답(앞 600자)을 붙인다 |
| 켜기 | `llm_worker.bat` 또는 자동 켜기(`--install`, 로그온 + 5분마다). 워커가 LM Studio 서버·모델도 켠다 |

사용자가 CPU·GPU 를 쓰는 브라우저 실행(WebLLM 등)은 가능하지만 **처음에는 하지 않는다** (사용자 확정 09-28) —
첫 사용 때 수 GB 내려받기, 사무용 PC 의 내장 그래픽에서는 한국어 질이 떨어지고, RPA 가 도는 PC 와 자원을 다툰다.
질문이 늘어 전용 PC 하나로 모자라면 그때 옵션으로 붙인다.

## D-9. 사용량(트래픽) — 과금 근거 (09-28, 사용자 요청)

웹 서버를 RPA 와 잇는 목적은 **RPA 를 얼마나 썼는지(트래픽)** 를 보이는 것이다. 나중에 이 숫자로 요금을 받는다.
관리자는 모든 업체를, 업체 사용자는 자기 업체만 본다 (RLS — 화면이 숨기는 것이 아니다).

| 무엇 | 어떻게 |
| --- | --- |
| 세는 단위 | `docs/BILLING.md` 1·2절 그대로 — 메일 = 메일 사이트 한 곳 1회(처리한 메일이 있을 때만 — 받기 실패 제외, 엑셀 아닌 것 포함. 09-30) / 주문수집·매출처리·물류대기·물류관리 = 끝까지 마친 실행 1회. 실패·할 일이 없어 건너뜀은 세지 않는다 |
| 어디서 세나 | **서버가 `run_steps` 에서 센다** (`refresh_usage`). 단계가 `done` 인 것만 센다. RPA 가 따로 '행위 수' 를 보내지 않는다 — 가중치·규칙을 서버에서 바꿀 수 있다 (BILLING 1절 '모듈별 가중치는 나중에 서버에서') |
| RPA 쪽 (09-28 빌드부터) | 메일 단계가 건수(`total`·`failed`)를 보낸다. 할 일이 없던 단계는 `skipped` 로 둔다 — 물류관리 전표 0건 / 물류대기 보류·저장할 것 없음 / 매출처리 0건. 물류관리 저장 실패는 `failed_items=1` 로 알려 세지 않는다 |
| 표 | `usage_daily` — (PC, 날짜) 한 줄. 날짜는 **한국 시각**, 서버가 받은 시각(`received_at`) 기준. `actions` = 네 기능 합 (생성 열) |
| 갱신 | cron 10분마다 최근 3일 안에 움직인 실행이 있는 (PC, 날) 을 통째로 다시 센다 (몇 번 해도 같다). 처음 적용 때 179일치를 채웠다 |
| 보관 | **지우지 않는다** — `runs` 는 180일 뒤 지워져도 사용량은 남는다. PC·업체 행은 지우지 말고 폐기(`revoke_device`) |
| 웹 | [사용량] 탭 — 이번 달·지난달·최근 30일, 날짜별 막대, 기능별·PC별 표, 관리자는 업체별 표(누르면 그 업체로), 엑셀 내려받기. [요약] 첫 카드 = 이번 달 사용 횟수 |
| 아직 | 잔액·차감·충전·월 마감(확정) 은 없다 (BILLING 3·4단계). 09-28 전 빌드는 메일 건수를 보내지 않아 메일이 0 으로 센다. 지난 보류만 남아 물류대기가 [저장]을 눌렀는데 줄지 않은 경우는 1회로 센다 (저장이 뒤에서 돌면 가릴 수 없다) |

## D-10. 규칙 — 보고·웹·보안 (옛 B-3·B-5·B-6 중 지금도 맞는 것, 09-29 옮김)

코드(`server/schema.sql`·`orchestrator/telemetry.py`·`web/app.js`)와 훅(`check_rpa_rules.py`·`guard_sql.py`)이 따르는 규칙이다.

**`ingest` 검사 순서** (`security definer`, `set search_path = ''`, 이름은 전부 `public.`):
1. 크기 상한 — 본문 64 KB, 이벤트 100개를 넘으면 400
2. 신원 — 빌드 ID sha256 + MachineGuid (`private.bind_device`). 없거나·폐기됐거나·업체가 중지됐거나(`accounts.suspended_at`, 10-07)·다른 PC 면 **같은 문구로** 401 (이유를 알리지 않는다)
3. 하루 상한 — 50실행·2만 이벤트를 넘으면 429 (빌드 ID 가 새도 DB 를 못 채운다)
4. `runs` 를 먼저 보장 (`on conflict do nothing`) — `run_start` 가 유실돼도 고아가 안 생긴다
5. run_id 소유 — 다른 기기의 실행이면 요청 전체 거부 (run_id 는 웹 주소에 보여 비밀이 아니다)
6. 종류별 반영 — `step` 은 `seq` 가 클 때만, `log`·`attend` 는 `(run_id, seq)` 충돌 무시, `run_end` 는 `lost` 를 진짜 끝으로만 바꾼다. 시각 판정은 서버 `now()`, pg_cron 은 UTC

| 무엇 | 규칙 |
| --- | --- |
| 권한 | 표 권한은 anon·authenticated 모두 0 (authenticated 는 select + RLS). 함수 실행 권한도 기본으로 뺀다(`alter default privileges … revoke execute`) — **Supabase 는 새 함수에 anon 실행을 기본으로 준다.** 쓰기는 RPC 로만 |
| RLS | 모든 표. 읽기 `private.is_admin() or account_id in (select private.my_account_ids())`, 도우미는 `private` 스키마(API 비노출). `service_role` 키는 어디에도 두지 않는다 |
| 사용자 | 이메일 가입 끔 — 관리자가 콘솔에서 만들고 `account_members` 에 넣는다. 비밀번호 재설정도 콘솔 (무료 SMTP 는 시간당 2통). **본인 비밀번호 바꾸기는 웹 [비밀번호 변경]**(`#/account`, 10-07) — 현재 비밀번호로 다시 확인 → `updateUser` → 다른 곳의 로그인 끊기(`signOut({scope:"others"})`). 8~72자 |
| 보고기 | RPA 스레드는 `put_nowait` 만 — 전송을 기다리지 않는다. 5xx·네트워크·타임아웃만 outbox, **401·400·429 는 버리고** 사용자 로그에 한 줄. outbox 에 빌드 ID 를 넣지 않는다. ssl 기본 검증을 끄지 않는다 — 인증서 오류면 PowerShell 로 서버에 한 번 접속해 Windows 가 루트 인증서를 받게 하고 새 문맥으로 한 번 더 보낸다(프로세스당 1회, 갓 설치한 Windows 대비, 10-07). dry-run 은 보내지 않는다 |
| 웹 | DOM 은 `textContent` 만 (`innerHTML`·`eval` 금지 — 서버 문자열은 PC 가 보낸 것이다). CSP `script-src 'self'` + CDN 은 SRI 고정, 인라인 스크립트 없음. 못 읽은 숫자는 '—' (지어내지 않는다). 세션은 `sessionStorage` + 로그아웃 (무료 플랜엔 세션 시간 제한이 없다) |
| cron | `mark_lost` 5분(10분 무응답 → `lost` + 알림) · `purge_old` 매일(180일, `usage_daily` 는 남긴다) · `send_alerts` 1분(`pg_net` → 메일 API, 키는 Vault, 10-02). **Edge Function 은 만들지 않는다**. `ingest` 는 run_id 없는 이벤트를 idle·alert 말고는 400 으로 거른다 (10-02) |
| 개인정보 | ERPia 알림 원문·첨부 파일명·호스트명·경로·예외 원문은 싣지 않는다. 상품명이 나가므로 업체 약정에 항목을 적고 국외 이전(Supabase) 고지를 확인한다 |
| 위·변조 | 빌드를 가진 사람의 조작은 못 막는다 (`docs/BILLING.md` 5절). `seq` 역행·구멍, 시각 차 5분 이상은 표시만 |
