# 설정 설명서 (`config/settings.local.json`)

환경마다 다른 값은 **이 파일 하나**에 모은다. 코드에는 경로도 계정도 쓰지 않는다. (RPA 설정이 아닌 값은 `.env`, 꼴은 `.env.example`. 둘 다 git 에 올리지 않는다, 10-02)

| 어디 | 경로 |
| --- | --- |
| 개발 | `config\settings.local.json` |
| 배포본 | **exe 옆** `config\settings.local.json` (예: `dist\run\config\`) |

항목 정의는 `config/fields_collect.py` / `fields_erpia.py` 의 `DEFAULTS` 다
(`config/settings.py` 가 둘을 합친다). **여기 없는 키는 무시하고 경고만 남긴다.**

고칠 때 주의

- **역슬래시는 두 번 쓴다.** `"C:\\Users\\..."` — 한 번만 쓰면 JSON 이 깨져 설정을 **하나도** 못 읽는다
- 값이 없으면 `""` 또는 `[]` 로 두고 **키는 지우지 않는다**
- **기본값이 없다** (10-02). 화면에서 고르는 값이 비면 실행 창 [실행] 이 '입력 필요' 로 잠기고, 칸이 없는 값(빌드에 굽는 값)이 비면 그 기능이 시작하지 않는다 — 빌드 프로그램도 꼭 필요한 값이 비면 굽지 않는다. 남은 것은 안전용 꺼짐 값(`auto_run_enabled`·`run_modules_locked`·`browser_headless` 의 `false`, `auto_start` 의 `null`)과 '비우면 조건 없음' 목록뿐이다
- **비밀번호는 감싸서 저장된다** (2026-09-17). 화면에서 넣은 값은 `dpapi:` 로
  시작하는데, **그 PC·그 Windows 계정에서만 풀린다** — 폴더를 복사해 가도
  다른 PC 에서는 못 쓴다. 손으로 평문을 적어도 읽히고, 다음 저장 때 감싸진다.
  빌드에 구운 값은 `baked:` 이고 **다른 PC 에서도 풀린다**(그래서 약하다 —
  키가 프로그램 안에 있다. 자세한 것은 `utils/secret.py` 머리말)
- 고친 뒤 확인: `.venv\Scripts\python.exe -m tools.test_collect --check`

`.env` 에 두는 값 — `SUPABASE_URL`·`SUPABASE_PUBLISHABLE_KEY` (웹 대시보드 주소·공개 키. `tools/build_web.py` 가 `build/web` 의 자리표시를 채운다) / `BAKED_SEED` (빌드에 굽는 비밀번호를 감싸는 씨앗. 빌드 때 `config/baked.key` 로 묶인다). RPA 가 쓰는 계정·비밀번호·서버 값은 `.env` 가 아니라 `settings.local.json` 에 둔다

## 1. ERPia 프로그램

| 명칭 | 예시값 | 설명 |
| --- | --- | --- |
| `target_exe` | `<ERPia 설치 폴더>\\<실행 파일 이름>` | ERPia 실행 파일. **비었거나, 이 PC 에 없거나, 파일 이름이 `target_exe_name` 과 다르면 실행용 창이 켤 때와 [실행] 때 찾아 넣는다** (Program Files 아래 두 단계 → 프로그램 등록 정보 → 바로가기에서 그 이름으로, 09-23 / 09-29 / 10-02). [실행] 때도 못 찾으면 실행하지 않고 실패로 남긴다(로그·[실행 기록]·알림 창). [설정] 의 [찾기] 로도 넣는다 |
| `target_exe_name` | `<실행 파일 이름>` | ERPia 실행 파일 **이름**(경로 없이, 10-02). **굽는다** — 실행 창에 칸이 없다. 실행용은 ERPia 기능에 필요하고, 비면 [실행] 이 '입력 필요' 로 잠긴다(빌드 프로그램도 굽지 않는다). `find_exe` 가 이 이름으로 이 PC 의 ERPia 를 찾고, `is_erpia_exe`·`logged_in_pids` 도 이 이름으로 ERPia 를 가린다 |
| `target_work_dir` | `<ERPia 설치 폴더>` | 실행할 때의 작업 폴더. 비우면 exe 가 있는 폴더 |
| `target_args` | `[]` | 실행 인자. 바로가기에 인자가 있으면 넣는다 |
| `window_title_re` | `""` | 메인 창 제목 정규식. 비우면 기본 판정(`업체코드 - 아이디`) |
| `window_class_name` | `""` | 메인 창 class 이름. 비우면 기본 판정 |
| `login_company_code` | `comp01` | ERPia 로그인 업체코드. **없으면 실행 불가** |
| `login_user_id` | `user01` | ERPia 로그인 아이디. **없으면 실행 불가** |
| `login_password` | `********` | ERPia 로그인 비밀번호. 저장할 때 감싼다(`dpapi:`). **없으면 실행 불가** |

`target_args` / `window_title_re` / `window_class_name` 는 평소 건드리지 않는다.
다른 버전의 ERPia 에서 창 제목이 달라졌을 때 쓰는 예비 항목이다.

## 2. ERPia 업무

| 명칭 | 예시값 | 설명 |
| --- | --- | --- |
| `run_modules` | `["mail", "orders", "logistics_wait", "logistics"]` | **실행할 기능** (통합·실행용만). 고른 것만 이 순서로 돈다. 최소 1개. `mail` 메일 엑셀 받기 / `orders` 주문수집·매출처리 / `logistics_wait` 물류대기 / `logistics` 물류관리 |
| `run_modules_locked` | `false` | **기능 고정 빌드** (실행용만, 빌드 프로그램이 굽는다 — `docs/BUILD.md`). `true` 면 exe 는 구운 `run_modules` 만 돌고 실행 창에서 바꿀 수 없다 (예약도 그 안에서만). exe 옆 설정으로는 못 푼다 |
| `collect_sources` | `["excel", "site"]` | 주문수집 방식. **최소 1개, 최대 2개.** 둘 다면 순서와 무관하게 엑셀 → 자동 |
| `excel_dir` | `%USERPROFILE%\\Desktop\\<엑셀 폴더>` | 엑셀수집이 훑을 **폴더**(파일 하나가 아니다) |
| `delivery_company` | `택배사A` | 물류관리에서 고를 택배사. 드롭다운 항목과 **완전일치** |
| `delivery_box` | `박스A` | 물류관리에서 고를 박스. **완전일치** |
| `logistics_mode` | `자동` | 물류관리 상단 [자동/수동] 콤보에 맞출 값. `자동` 이면 저장 뒤 [운송장출력], `수동` 이면 [엑셀파일생성] 을 누른다. 비우면 [실행] 이 '입력 필요' 로 잠긴다 |
| `sales_mode` | `전체` | 매출처리 방식 (10-01). `전체` = [매출처리] 단추 — **조회되지 않은 미매출 주문까지** 처리 / `선택주문` = 조회된 주문만 전부 체크해 우클릭 [선택주문 매출처리]. 비우거나 다른 값이면 [실행] 이 '입력 필요' 로 잠긴다 |
| `hold_exclude_codes` | `["8800000000001"]` | 물류대기에서 **배송보류를 걸지 않을** 상품코드. 완전일치 |
| `customer` | `""` | **업체 전용 빌드**의 업체 id (10-08, `docs/CUSTOMERS.md`). 빌드 프로그램이 고르고 **굽고 잠근다** (`LOCKED_KEYS`). 비면 원본. 그 업체의 칸(`cx_` 로 시작)이 이 파일에 더해지고 실행 창 [설정] 탭 업체 묶음·웹에 보인다. 개발 폴더에서 시험할 때는 이 키 대신 환경변수 `RPA_CUSTOMER` |
| `excel_passwords` | `{"사이트B": "0000"}` | 암호 걸린 엑셀의 비밀번호. **사이트명별** |
| `excel_password` | `""` | 사이트별 값이 없을 때 쓸 기본 비밀번호 |
| `collect_site_code` | `""` | **개발 도구 전용.** 사이트코드로 한 건만 올릴 때 |
| `excel_path` | `""` | **개발 도구 전용.** 엑셀 파일 하나를 지정 |

`collect_sources` 값: `"site"` = 자동수집(ERPia 가 사이트에서 직접 가져온다) /
`"excel"` = 엑셀수집(엑셀 파일을 사이트 행에 올린다).

> ★ **통합·실행용은 `"excel"` 을 반드시 넣는다.** 메일로 받은 엑셀을 매니페스트로
> 넘겨받아 올리는데, `["site"]` 만 두면 **한 건도 올리지 않고** 경고만 남긴다.

## 3. 메일 (수집)

> ★ **메일 사이트 연결(사이트 파일)은 git 밖 `collect/sites/local/` 에 둔다** — 원본에는 메일 사이트가 없다. 있으면 빌드에 같이 묶이고, 없으면 메일 기능이 돌지 않아 실행 창이 '메일 사이트 연결' 입력 필요로 잠근다 (10-02, `docs/SITES.md`)

| `mail_senders` | `[]` | 대상 발신자 주소 완전일치 목록. **비우면 발신자를 보지 않는다** |

`mail_senders` / `mail_sites` 는 **비워 두는 것을 기본으로 본다** — 사이트가 늘거나
이름이 바뀔 때마다 이 파일을 고쳐야 하기 때문이다(사용자 확정 2026-09-10).

## 5. 인증 문자 (수집)

| 명칭 | 예시값 | 설명 |
| --- | --- | --- |
| `phone_os` | `android` | 인증 문자를 받는 휴대폰: `android` / `ios`. **`ios` 는 아직 지원하지 않는다.** 비면 실행 불가 |
| `sms_source` | `phonelink` | 문자를 읽는 방법: `phonelink` / `adb` / `auto`. **없으면 실행 불가** |
| `adb_connection` | `usb` | adb 연결 방식: `usb` / `wireless`. `sms_source` 가 `adb`·`auto` 일 때만 보고, 그때 비면 실행 불가 |
| `sms_senders` | `[]` | 인증 문자 발신번호 완전일치 목록. 비우면 발신자 조건을 걸지 않는다 |
| `sms_keyword` | `<인증 문자에 든 말>` | 인증 문자를 고르는 말 (사이트마다 다르다). **없으면 실행 불가** |
| `adb_path` | `""` | `adb.exe` 경로. 비우면 PATH 에서 찾는다 |
| `adb_wireless_address` | `192.0.2.50:41253` | 무선 디버깅 주소 `IP:포트`. `adb`+`wireless` 면 **없으면 실행 불가** |

`sms_source` 고르는 법

| 값 | 케이블 | 그 밖에 필요한 것 |
| --- | :---: | --- |
| `phonelink` | 불필요 | PC 의 [휴대폰 연결] 앱이 `연결됨`. 폰에서 **모바일 데이터 동기화** 허용 |
| `adb` + `usb` | **필요** | 폰의 [개발자 옵션 → USB 디버깅] + 허용 창 승인 |
| `adb` + `wireless` | 불필요 | PC 와 폰이 같은 네트워크. `adb_wireless_address` 채우기 |
| `auto` | — | phonelink 를 먼저 보고, 준비가 안 됐으면 adb 로 넘어간다 |

**USB 를 쓰지 않으려면 `phonelink` 로 둔다.** 그 경우 `adb_*` 세 키는 읽지 않는다.
`adb_wireless_address` 는 페어링 포트가 아니라 **연결 포트**다.

## 6. 자동 실행 (예약)

| 명칭 | 예시값 | 설명 |
| --- | --- | --- |
| `auto_run_enabled` | `false` | 예약 실행을 켠다. **기본은 꺼짐.** 켜면 사람 없이 실계정 저장이 돈다 |
| `auto_run_mode` | `daily` | `daily` = 정해진 날·시각 / `interval` = 정해진 간격. 예약을 켰는데 비면 예약이 돌지 않고 화면이 알린다 |
| `auto_run_times` | `["평일 09:00 mail,orders", "매월 25일 18:00"]` | `daily` 에서 쓴다. 예약 줄 목록, **최대 12개** (아래 꼴만). 끝에 기능을 붙일 수 있다 |
| `auto_run_interval_minutes` | `120` | `interval` 에서 쓴다. 분. **10 ~ 1440** — 비었거나 범위 밖이면 예약이 돌지 않고 화면이 알린다 |
| `auto_start` | `null` | **자동 켜기** (09-28, 실행용 빌드본만). `true` 면 PC 에 로그온할 때 켜고, 꺼져 있으면 **5분 안에 다시 켠다** (최소화로). `null` = 아직 안 물음 — 처음 켤 때 묻는다. 실행 창 [설정] 탭 [프로그램] 묶음의 체크로 바꾼다 (09-29). **굽지 않는다** |

`auto_run_times` 한 줄의 꼴 (09-21 — 날 조건 추가). 실행용 창에서는 [반복]·요일·시각을 골라 [추가] 한다.

| 꼴 | 뜻 |
| --- | --- |
| `09:00` / `매일 09:00` | 매일. 예전 설정(`"09:00"`)도 그대로 읽는다 |
| `월수금 13:00` / `평일 09:00` / `주말 10:00` | 그 요일마다 |
| `매월 25일 09:00` | 매월 그날. **그날이 없는 달은 건너뛴다** (31일 → 30일까지인 달은 안 돈다) |
| `2026-09-25 14:00` | 그날 한 번. 지나면 돌지 않는다 (목록에 "지났음" 으로 남는다) |

끝에 **그 예약에 돌릴 기능**을 붙인다 (09-21 (7)): `"평일 09:00 mail,orders"` / `"매월 25일 18:00 logistics"`.
기능 이름은 `run_modules` 와 같은 `mail` / `orders` / `logistics_wait` / `logistics`, 쉼표로 잇고 띄어 쓰지 않는다.
실행용 창에서는 [이 예약의 기능] 을 체크하고 [추가] 한다.

| 기능을 | 그 회차에 도는 것 |
| --- | --- |
| 붙였다 | 붙인 기능만 (순서는 늘 메일 → 주문수집·매출처리 → 물류대기 → 물류관리) |
| 안 붙였다 (예전 설정) | 실행용 창의 [실행할 기능] 선택(`run_modules`) |
| 같은 시각에 걸린 줄이 여럿 | 기능을 **합쳐** 한 번 돈다 (예: `매일 09:00 mail` + `월수금 09:00 logistics` → 월수금은 둘 다) |
| `interval` 모드 | 실행용 창의 [실행할 기능] 선택 |

★ **형식이 틀린 값은 버리고 화면에 알린다.** `"9시"` / `"0900"` / `"월,수 09:00"` / 모르는 기능이 붙은 줄은
받지 않는다 — 0시로 읽어 버리면 **새벽에 실계정이 돈다.**
★ 예약 줄에만 있는 기능의 입력칸(택배사 등)도 실행용 창에서 **잠그지 않는다** — 그 예약이 쓴다.

★ **잠긴 화면에서는 자동화가 동작하지 않는다.** Windows 제약이고 우회할 수 없다
(`click_input()` 이 예외 없이 넘어가지만 버튼이 눌리지 않는다). 그래서 예약 시각에
화면이 잠겨 있으면 **그 회차를 건너뛰고 기록만 남긴다.** PC 가 켜져 있고 사람이
로그온한 상태가 전제다.

건너뛰는 경우는 다섯뿐이다.

| 왜 | 그래서 |
| --- | --- |
| 화면이 잠겼다 | 건너뛴다 |
| 앞 회차가 아직 돈다 (사람이 [실행] 을 눌러 시작하는 중 포함) | 건너뛴다 (같은 아이디 동시 로그인을 서버가 막는다) |
| 사람이 [일시정지] 를 눌렀다 (09-29 전 이름 [잠시 멈춤]) | 건너뛴다. **RPA 프로그램을 껐다 켜도 이어진다** (exe 옆 `logs\autorun_state.json`, 10-02). 창 [예약] 탭과 웹의 [일시정지]·[계속하기] 는 같은 상태 — 어느 쪽에서 멈추고 어느 쪽에서 풀어도 된다 |
| 시작 시각을 10분 넘게 놓쳤다 (PC 잠자기·꺼짐) | 건너뛴다 — 깨어나자마자 예고 없이 돌지 않게 (10-02) |
| 사람이 예약 5분 전 경고 창에서 [이번만 건너뛰기] 를 눌렀다 | 그 한 번만 건너뛴다. 다음 예약은 그대로 (10-02) |

**건너뛴 회차는 몰아서 돌리지 않는다.** 다음 예약 시각을 기다린다.
실패해도 곧바로 재시도하지 않고 다음 예약을 기다린다(사용자 확정 2026-09-16).
건너뛴 회차는 [실행 기록] 에 남고(`logs\history.jsonl`), 같은 이유로 이어지면 한 줄에 횟수로 보인다 (10-02).

예약 전에 하는 일 (10-02, 설정 키 없음 — 값은 `gui/run_app.py` 상수)

| 언제 | 무엇 |
| --- | --- |
| 5분 전 | 이 PC 에 **같은 업체코드·아이디로 로그인된 ERPia** 가 있고 그 회차에 ERPia 기능이 있으면 맨 위 알림 창 — "실행하면서 그 창을 닫는다, 저장하라". [이번만 건너뛰기] — 그 한 번만 돌지 않는다(다음 예약은 그대로, [실행 기록]·서버에 건너뜀으로). 아무도 안 누르면 예약 시각에 그대로 돈다 (10-02 사용자 결정 — 미루기 대신) |
| 30분 전부터 5분마다 | 그 회차에 메일 기능이 있으면 휴대폰 인증 준비를 **보기만 한다** (앱을 띄우거나 [다시 시도] 를 누르지 않는다). [홈] '다음 예약' 둘째 줄에 결과. 처음 '안 됨' 이면 알림 창 1회 + 서버 알림(업체 담당자 메일). 실행을 막지는 않는다 |

`interval` 은 **앞 회차가 끝난 시각**부터 센다. 시작 시각부터 세면 흐름이 간격보다
오래 걸릴 때 쉬지 않고 계속 도는 상태가 된다. 그 차례가 이미 지났으면(건너뛴 뒤·간격을 줄인 뒤) **지금부터** 센다 (10-02).

지난 회차의 결과는 **실행용 창의 `자동 실행` 칸**에 표로 남는다. 무인 실행이라
사람이 나중에 보는 유일한 창구다.

## 7. 서버 보고

설계는 `docs/SERVER_PLAN.md`. **셋 다 있어야** 보내고, 하나라도 비면 보내지 않고 지금처럼 돈다.

| 명칭 | 예시값 | 설명 |
| --- | --- | --- |
| `server_url` | `https://abcd.supabase.co` | Supabase 프로젝트 URL (`/rest/v1/` 는 뗀다). 굽는다 |
| `server_anon_key` | `sb_publishable_...` | 공개 키 — Project Settings → API Keys 의 **Publishable key** (예전 프로젝트는 Legacy 탭의 anon `eyJ...`). 굽는다. 비밀이 아니다 |
| `server_build_id` | `bld_...` | **빌드 ID** (09-28). **빌드할 때 서버가 발급하고 굽는다** — 빌드 프로그램이 관리자 계정으로 `register_build` 를 불러 받는다. 사람이 넣는 칸은 없다. 그 exe 가 **처음 켜지는 PC 에 묶이고**, 다른 PC 로 복사하면 401 이라 실행이 잠긴다 |

LLM 전용 PC 에만 있는 값 (09-28): `llm_worker_key` — 사용법 질문 워커(`llm/worker.py`)의 키. `python llm\worker.py --init` 이
만들어 감싸 넣는다(`dpapi:`). **RPA 설정 항목이 아니다** — `llm_` 로 시작하는 키는 RPA 가 읽지도 굽지도 않고 "모르는 키" 경고도 하지 않는다.
서버에는 해시만 넣는다 (`server/schema.sql` 8절).

빌드 프로그램에만 있는 값 (관리자 PC 에만 남고 **굽지 않는다**): `build_account_name` 업체 이름 /
`build_label` 이 빌드의 이름(대시보드 PC 표에 보인다) / `build_admin_email`·`build_admin_password`
대시보드 관리자 계정.

보내는 것: 실행 시작/끝, 단계 상태, 화면의 사용자 로그 줄, 확인할 것, 30초 심박(잠김·일시정지), 앱이 떠 있는 동안 15분마다 "살아 있음·다음 예약",
건너뛴 예약 회차, **사람 손이 지금 필요한 일**(ERPia 업데이트 UAC 동의 대기·예약 전 휴대폰 점검 실패 — 따로 한 건씩, 10-02).
서버는 무인 실행(예약·원격)의 실패·확인할 것과 위 알림을 **업체 owner·관리자에게 따로 한 통씩 메일**로 보낸다 (Vault 에 메일 키가 있을 때만, `server/README.md`). 시험 실행·점검·미리보기는 보내지 않는다. 서버가 죽어도 실행은 그대로 돌고, 못 보낸 것은 `logs/outbox.jsonl` 에 두었다가 다음에 보낸다.

**실행 창이 뜰 때 서버에 한 번 확인한다** (`ingest` 를 빈 이벤트로 부른다). 그 자리에서 이 PC 에
묶이거나, 다른 PC 에 묶인 빌드면 거부돼 [실행]이 잠긴다. 서버가 죽어 있으면 1분마다, 거부(폐기·다른 PC·**업체 중지**)됐으면
10분마다 다시 해 본다 — 관리자가 업체 중지를 풀면 껐다 켜지 않아도 풀린다 (10-07).

**웹에서 보는·바꾸는 설정과 명령** (09-28, 10-07 개편): 확인을 통과하면 30초마다 서버에 묻는다 (`orchestrator/remote.py`).
★ **설정은 이 파일에만 있다** (사용자 확정 10-07) — 서버는 설정을 저장하지 않는다. 서버에는 로그·사용량만 남는다.

| 무엇 | 동작 |
| --- | --- |
| 웹에서 설정 보기 | 웹이 PC 화면을 열면 PC 에 묻는다 → PC 가 다음 확인(30초 안)에 지금 값을 답한다 → 웹이 한 번 읽으면 서버가 지운다. PC 가 꺼져 있으면 볼 수 없다 |
| 웹에서 바꾼 설정 | 바꾼 키만 온다. 받으면 exe 옆 `settings.local.json` 에 저장하고 화면 칸에 옮긴다 (서버는 건넨 뒤 지운다, 2분 안에 안 가져가면 버린다). **실행 중이면 끝난 뒤** 적용한다. 09-29 부터 **PC 가 실행 중이면 웹에서 저장할 수 없다** — 웹이 칸을 잠그고 서버(`set_device_settings`)도 423 으로 거절한다 |
| 웹에서 바꿀 수 있는 키 | `run_modules`(기능 고정 빌드는 PC 가 버린다)·`auto_run_*` 4개·`collect_sources`·`delivery_company`·`delivery_box`·`logistics_mode`·`sales_mode`(10-02)·`hold_exclude_codes`·`sms_source`·`adb_connection`·`adb_wireless_address`·**업체 빌드의 `cx_` 칸** (10-08 — 웹은 PC 가 보낸 칸 정의로 그린다) — **비밀번호와 PC 의 경로는 없다** (보지도 바꾸지도 못한다) |
| 창에서 고친 값 | 이 파일에만 저장한다 — 서버에 올리지 않는다 (10-07) |
| [실행] | 예약 회차처럼 무인으로 돈다 (이력·리포트의 '어떻게' = `원격 실행`). 실행 중·잠긴 화면·서버 확인 전이면 시작하지 않고 사유를 웹에 남긴다. 10분 안에 못 받은 명령은 버린다 |
| [RPA 종료] / [일시정지]·[계속하기] | 창의 [중단] 과 같다 (확인 창 없이) / 창 [예약] 탭의 [일시정지]·[계속하기] 와 같다 (09-29 이름을 맞췄다) — **예약**을 멈춘다. 웹에서 [RPA 종료] 는 실행 중일 때만, [일시정지] 는 일시정지가 아닐 때만, [계속하기] 는 일시정지일 때만 눌린다 |

## 알아 둘 규칙

### 엑셀수집 — 올릴 사이트는 **파일 이름**으로 정한다

`excel_dir` 바로 아래의 엑셀(`.xlsx` / `.xls` / `.xlsm`)을 전부 올린다.
파일명 **첫 밑줄(`_`) 앞부분**이 사이트명이고, 사이트 그리드의 `사이트명` 과
**완전일치**하는 행에 올린다. 하위 폴더는 보지 않는다.

| 파일명 | 결과 |
| --- | --- |
| `사이트A_20260908.xlsx` | 사이트명 `사이트A` |
| `주문내역.xlsx` | 밑줄이 없다. 건너뛴다(경고) |
| `~$사이트A_1.xlsx` | 엑셀을 열어 둘 때 생기는 임시 파일. 건너뛴다 |

업로드가 실패하면 **한 번만 더** 시도하고 그 파일은 건너뛴다. 실패한 파일은 로그 끝 요약에 남는다.

### 암호가 걸린 엑셀

찾는 순서는 `excel_passwords[사이트명]` → `excel_password` → **중단**이다.
**값이 없으면 아무것도 넣지 않고 멈춘다** — 틀린 값을 반복 입력하면 파일이 잠긴다.

### 물류대기 — 보류에서 뺄 상품

`hold_exclude_codes` 의 상품코드는 부족수량이 있어도 보류를 걸지 않는다.
상단 재고 그리드의 `상품코드` 와 **완전일치** 비교다(부분 일치는 하지 않는다).
보류를 다 건 뒤 하단을 훑어 실제로 걸렸는지 확인하고, 모자라면 경고를 남긴다.

### 대상 메일 / 첨부 판정

세 조건을 모두 만족하는 메일만 연다: 발신자(`mail_senders`) + 제목의 `[사이트명]`
(`mail_sites`) + 첨부 있음. 목록에서는 "첨부가 있다"까지만 알 수 있고,
엑셀인지는 열어 봐야 안다.

| 매니페스트 `status` | 뜻 | 메일 상태 | 다음 실행 |
| --- | --- | --- | --- |
| `downloaded` | 받았다 | 읽음 | 업로드 대상 |
| `skipped` | 열어 보니 엑셀 첨부가 아니었다 | **읽음 유지** | 다시 열지 않는다 |
| `failed` | 받는 데 실패했다 | **읽음 그대로** | 기록을 보고 **읽음이어도 다시 연다** (`mail_days_back` 기간 안의 날짜 기록) |

**메일을 읽지 않음으로 되돌리지 않는다** (사용자 확정 09-30 — 09-08 "실패는 미읽음으로 되돌림" 을 대체).
`skipped` 를 다시 열지 않는 이유: 다시 열어도 결과가 같아 **같은 메일만 반복해서 열게** 된다.

저장 규칙: `<download_base_dir>\YYYY-MM-DD\YYYY-MM-DD_차수_사이트명\` + `manifest.json`.
차수는 **날짜별로 001 부터** 다시 시작한다.

메일 목록은 **`mail_days_back` 안쪽이 끝날 때까지 페이지를
넘긴다** (09-21). `-1`(기간 조건 없음)이면 끝 페이지까지, 둘 다 **20페이지가 상한**이다.
수신일시를 읽는 법은 사이트 파일이 정한다(`MailRow.received`) — 못 읽은 메일은 기간 조건이 있을 때 건너뛴다.

★ [휴대폰 연결] 은 수신 시각을 **분 단위**로만 준다. 같은 분에 온 직전 인증번호를
시각만으로는 가릴 수 없어서, 요청 직전 대화 본문을 찍어 두고 **그때 없던 문자만** 쓴다.

## 값은 세 겹으로 쌓인다 (나중에 읽은 것이 이긴다)

| 순서 | 어디서 | 언제 |
| --- | --- | --- |
| 1 | `config/fields_*.py` 의 `DEFAULTS` | 항상. **기본값이 없다** — 안전용 꺼짐 값만 있다 (10-02) |
| 2 | **빌드에 구운 값** (`config/settings.baked.json`, 번들 안) | **실행용 빌드(`RPA_1.exe`)만** |
| 3 | `config/settings.local.json` (개발 폴더 / exe 옆) | 있으면 항상. 위 둘을 덮는다 |

굽는 원본은 개발 폴더의 `config/settings.local.json`, 굽는 도구는
`tools/bake_settings.py`, 넣는 곳은 `build_run.spec` 이다(`docs/BUILD.md`).
`collect_site_code` / `excel_path` 는 개발 도구 전용이라 **굽지 않는다.** `target_exe` / `target_work_dir` 도 굽지 않는다 — 실행용 창이 그 PC 에서 찾아 채운다 (09-23). 대신 ERPia 실행 파일 **이름** `target_exe_name` 을 굽는다 (10-02). `download_base_dir` 도 굽지 않는다 — 기본값이 없어 그 PC 에서 [찾기] 로 고른다 (10-02).
빌드 프로그램 전용 값 넷(`build_*`, 관리자 계정을 포함한다)도 굽지 않는다 (09-28).

> ★ **`dist\run` 에 `settings.local.json` 을 미리 두지 않는다.** 3번이 2번을 덮으므로
> 빈 샘플을 두면 구운 값이 **전부 빈 값으로** 덮인다.

### 고정값은 로컬 설정이 못 덮는다 (09-28)

★ **`config/settings.py` 의 `LOCKED_KEYS` 는 예외다.** 구운 값이 최종이고, exe 옆
`settings.local.json` 에 같은 키를 적어도 무시한다 (경고 한 줄을 로그에 남긴다). 관리자가 정한
업체코드·아이디를 사용자가 바꿔 남의 계정으로 돌리는 것을 막는다.

| 고정되는 키 | |
| --- | --- |
| `login_company_code` · `login_user_id` | ERPia 업체코드·아이디 |
| `mail_url` · `mail_user_id` | 사이트 주소·아이디 |
| `run_modules_locked` | 기능 고정 여부. 이것이 참이면 `run_modules` 까지 고정된다 |
| `customer` | 업체 전용 빌드의 업체 (10-08) |
| `server_url` · `server_anon_key` · `server_build_id` | 서버 |

`target_exe_name` 은 굽기만 한다 — `LOCKED_KEYS` 가 아니라서 위 표에 없고(exe 옆 설정이 덮을 수 있다), 실행 창에 칸도 없다 (10-02).

실행용 화면에서 고칠 수 있는 구운 값은 아래 열세 가지뿐이고 (자동 실행 4개 키는 6절의 칸에서
따로 저장된다), 나머지는 구운 값을 쓴다.
고친 값은 exe 옆 `config\settings.local.json` 에 저장돼 다음 실행에 다시 뜬다. 09-29 부터는 [설정] 탭에서
**바꾸면 바로** 저장한다 (바뀐 값만. 빈 비밀번호·택배사·박스·경로는 저장하지 않는다 — 구운 값을 덮지 않게).

| 화면 항목 | 설정 키 |
| --- | --- |
| 실행할 기능 | `run_modules` |
| ERPia 프로그램 [찾기] (09-23) | `target_exe`, `target_work_dir` |
| 엑셀 저장 폴더 [찾기] (09-23) | `download_base_dir` |
| 사이트 비밀번호 | `mail_password` |
| ERPia 비밀번호 | `login_password` |
| 자동수집 / 엑셀수집 | `collect_sources` |
| 택배사 | `delivery_company` |
| 박스 | `delivery_box` |
| 자동/수동 | `logistics_mode` |
| 매출처리 (10-01) | `sales_mode` |
| 보류 제외 상품코드 (09-28) | `hold_exclude_codes` |

실행용(배포본은 이것 하나, 10-06)은 1~7절을 모두 쓴다. `excel_dir` 은 쓰이지 않는다(올릴 엑셀은 매니페스트에서 온다 — ERPia 만 도는 개발 도구 `test_flow` 가 쓴다).

## 이 파일에 없는 값

타임아웃은 `config/settings.py` 의 `Timeouts` 에, 재시도 상한은 자리마다 상수로 있다 (`docs/ERROR_HANDLING.md` 3절).
환경마다 바뀔 값이 아니라서 코드에 둔다.

| 이름 | 기본 | 뜻 |
| --- | --- | --- |
| `page_load` | 30초 | 웹 페이지 이동/로딩 |
| `sms_code` | 120초 | 인증 문자 도착 대기 (화면의 유효시간 2:00 과 맞췄다) |
| `phone_connect` | 300초 | [휴대폰 연결] 이 끊겨 [다시 시도]/새로 고침을 누른 뒤 **붙기를 기다리는 상한.** 붙으면 바로 넘어간다. 인증번호를 기다리는 도중에 끊기면 25초만 본다(문자 유효시간 2분) |
| `download` | 60초 | 첨부 다운로드 완료 |
| `login` | 30초 | 로그인 후 화면 전환 |
| `collect` | 4시간 | 사이트 전체 주문수집 (2~3시간까지 간다) |
