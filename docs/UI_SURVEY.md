## 화면: 로그인 · 로그인 직후 팝업

조사일 2026-09-03 (팝업 UIA 는 09-22 재조사). **식별값·팝업 본문·버튼은 `docs/CONTROLS.md` "로그인 창 — 확정"·"로그인 팝업 — 확정"**
이 원본이다. 여기에는 판정 근거와 함정·미해결만 둔다.

- 판정: 전부 **UIA 로 처리 가능.** 입력은 Value Pattern(`set_edit_text`) 성공. 로그인 버튼(`lbl_LoginBtn`, Text)은 Invoke 가
  안 돼 `click_input()` 이 정식 경로. 버튼 → 메인 창까지 약 7초 (09-03 실측).
- 입력 Edit 안의 **자식 Edit 은 숫자 `auto_id`(실행마다 바뀜)** — 쓰지 않는다. 부모 `txt_*` 를 쓴다.
- 완료 판정: 로그인 창 소멸 + 메인 창(`<업체코드> - <아이디>`) 등장.

### ★ 팝업은 최상위 창이 아니다 (탐색 함정)

`Desktop(backend="uia").windows()`(`top_level_only=True`)로는 **잡히지 않는다** — 팝업은 로그인 창의 자식이다.
그래서 ① 최상위 창 중 제목이 팝업 계열 → ② **로그인 창 하위 Window 중 제목이 팝업 계열(실제 경로)** → ③ 로그인 창
하위의 "확인" 계열 Button 순서로 본다. 본문은 확인 버튼에서 위로 올라가되 **로그인 창 직전까지만** 읽는다(넓히면 화면 라벨이 섞인다).

> 겪은 버그: 제목 정규식에 `실패` 가 없어 `로그인 실패` 를 놓쳤다 / 최상위 창만 뒤져 `경고` 를 놓쳤다 (09-03).
> `wrapper.descendants(title_re=…)` 는 TypeError 라 "버튼 없음" 으로 묻혔다 (09-22). 새 팝업 제목이 나오면 목록에 더한다.

**처리 방침** — 본문을 **읽어서 분기**한다 (무조건 닫으면 로그인 실패를 성공으로 착각한다). 팝업 처리는 5회까지.

| 본문 | 처리 |
|---|---|
| `2차 인증` 또는 `전화번호가 없어` | 계속 진행 |
| `동시에 같은 아이디` | 같은 계정으로 로그인된 앞 인스턴스만 닫고 한 번 더. 못 닫으면 중단 |
| `잘못된 아이디` / `비밀번호입니다` | 중단 — "아이디 또는 비밀번호가 올바르지 않습니다." |
| 그 외 | 중단 — 본문을 그대로 보여 준다. 방금 띄운 인스턴스는 닫는다 |

### 미해결 · 미확인

- `chk_KeepLogin` 이 Pane 이라 체크 상태를 읽을 수 있는지 미확인.
- 로그인 **오류 메시지** Control 미확인 (로그인 실패를 실제로 일으켜야 확인 가능).
- 2차 인증이 **설정된** 계정에서 뜨는 화면 미조사 (인증번호 입력 화면 추정).

## ★ 권한(Integrity Level) 문제 — 자동화 전체를 막는 조건

조사일: 2026-09-03

메인 창을 조사하려 했으나 **UIA로 창이 하나도 보이지 않았다.**
`visible_only=False, enabled_only=False`로 풀어도 0개.

원인:

| 프로세스 | elevated |
|---|---|
| `<실행 파일 이름>` (pid 1896, 사용자가 직접 실행) | **True (관리자 권한)** |
| RPA 파이썬 | False (일반 권한) |

Windows UIPI 규칙상 **낮은 무결성 수준의 프로세스는 높은 쪽의 UI를 열거하거나
조작할 수 없다.** 창 목록이 비어 보이는 것이지 창이 없는 게 아니다.

### 지금까지 로그인 자동화가 동작한 이유

RPA가 `Application().start()`로 **직접 띄운** 인스턴스는 RPA와 같은 일반 권한으로
실행된다. 그래서 그 인스턴스는 조작할 수 있었다.
사용자가 바로가기로 띄운(관리자 권한) 인스턴스는 조작할 수 없다.

### 해결 방향 (택일 필요)

| 방법 | 내용 | 영향 |
|---|---|---|
| A. RPA를 관리자 권한으로 실행 | `run.bat`을 관리자로 실행하거나 manifest에 `requireAdministrator` | 두 경우 모두 자동화 가능. 실행 시 UAC 확인 |
| B. ERPia를 일반 권한으로 실행 | 바로가기 속성에서 "관리자 권한으로 실행" 해제 | 프로그램이 관리자 권한을 요구하면 불가 |
| C. 항상 RPA가 직접 ERPia를 띄움 | 현재 동작 유지, 기존 창에는 붙지 않음 | 사용자가 이미 열어둔 창을 못 씀 |

**결정 (09-03 이후)**: C 로 간다 — RPA 가 늘 새 인스턴스를 직접 띄운다 (`application.start_new_instance`).
관리자 권한으로 뜬 인스턴스(업데이트 뒤)는 09-18 에 따로 처리했다 (`docs/BUILD.md` "관리자 권한").

### 진단 방법 (재현용)

프로세스 토큰의 `TokenElevation`을 비교한다.
자동화 시작 시 이 검사를 넣어두면 "창을 못 찾는다"는 오해를 막을 수 있다.

## 중복 실행

**가능하다. 확인됨 (2026-09-03).** 여러 인스턴스가 동시에 떠 있는 것을 실제로 관찰했다.

다만 **같은 아이디로 동시 로그인은 서버가 막는다** (`동시에 같은 아이디로 로그인할 수 없습니다.`).
프로세스는 여러 개 뜨지만 로그인은 하나만 된다.

판정 로직은 유지한다 (다른 환경/버전에서 단일 인스턴스일 수 있다).

| 결과 | 해석 |
|---|---|
| 새 프로세스에 창이 뜸 | 중복 실행 가능 ← **현재 환경** |
| 새 프로세스가 죽고, 다른 새 PID가 생김 | 런처형. 그 PID로 연결 |
| 새 프로세스가 죽고, 기존 PID만 있음 | 단일 인스턴스. 사용자에게 안내 후 재시도 |

메인 창 판정은 **반드시 실행한 PID로 한정**한다. 다른 인스턴스가 이미 로그인해 둔
메인 창(`user01 - user01`)을 성공으로 착각한 적이 있다.
